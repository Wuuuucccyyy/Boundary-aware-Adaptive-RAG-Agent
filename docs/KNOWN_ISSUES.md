# 已知问题与下一阶段

1. **自然语言解析覆盖有限。** 规则匹配无法稳健处理口语、否定、复杂实体和隐含多任务。保留未知子问题能减少漏报，但不能保证不错误合并或遗漏。
2. **证据验证只适用于当前合成数据。** 任务标签和逐字原文检查不能替代开放域蕴含验证、矛盾检测或来源质量判断。
3. **动态边界贡献混合。** 动态方法同时获得任务支持矩阵和覆盖选择策略。需增加共享选择器、仅去掉 N 的消融，不能据当前四组结果断言边界独立有效。
4. **数据规模和隔离不足。** 没有独立自然查询、独立人工标注、按文档或时间隔离的测试；不存在训练过的模型。当前结果只是原型证据。
5. **评分是代理。** 事实锚点可能误扣合理改写；有效引用不证明句句被支持。报告保留原文和人工复核样例，后续需盲审。
6. **费用与时延有限制。** 规则步骤消耗CPU但不消耗模型tokens；未配置价格时不输出货币成本。API缓存和负载不可完全控制。计时排除冷启动，文本工作预算是模块启动检查，时间截止是协作式。
7. **数据漂移尚无自更新。** 画像版本校验可阻止旧版本静默使用，但还没实现自动画像重建、反馈可信度判断或学习更新。
8. **模型错误采取明确失败。** 超时、截断、非法引用时不伪装为成功或静默切回离线结果；不自动重试，避免隐藏花费。
9. **首轮引用格式与评分粒度缺陷。** 冻结解析器只识别 `[id]`，未规范化模型的 `[doc_id: id]` 变体；后者未被计为有效引用，引用校验也未覆盖这种格式内的未知ID。某些只问凭证/联系方式的题却按整个任务要求期限/工作时间，造成评分过严。这些首轮结果保留，不能把代理分当成真实正确率；修复和新一轮验证单独跟踪，不能事后覆盖冻结结果。

下一阶段先扩充自然问题与独立标签，做误路由/库内检索/证据检查/生成错误分层诊断，比较正向 top-1/2/3 和关闭追加检索的消融，再做知识更新场景。只有成本与质量收益在更可靠数据上成立后，才考虑困难负例对比学习、离线反馈回放及受控边界更新。
