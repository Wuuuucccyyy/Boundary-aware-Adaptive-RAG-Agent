# 第一阶段实施计划

日期：2026-10-17。依据本地研究方向文档制定；原文不提交到仓库。

目标是交付可解释、可复现的规则版查询条件化边界原型，不训练模型，不预设动态边界更优。

1. 端到端演示（预计 1–2 小时）：Python 3.11 标准库；HR、财务、IT 合成库；版本化 P/Q/N 画像；子任务拆解；按未满足证据需求进行软惩罚和集合覆盖；统一 BM25 检索；证据检查、追加检索和预算。
2. 实验和测试（预计 1–2 小时）：全库、正向、固定负向、动态负向四种方法；统一生成器、检索参数、上限；测试集中记录所有失败，不按结果改标签；分类报告质量代理指标、必要源召回、调用量、token 和时延。
3. 交付（预计 30–60 分钟）：中文 README、配置、数据来源、实验原始轨迹、失败分析、测试、阶段 Issues 和 Git 提交；私有 GitHub 仓库。

资源：离线演示无需密钥、GPU 或外部数据。真实模型实验需要环境变量中的 API key 和明确模型 ID。GitHub 需要能创建/写入私有仓库的授权，若另有协作者还需用户名。

用户后续确认：使用其 CC Switch 中的 DeepSeek 配置；离线仅开发验证，在线才是正式对比；仓库改为公开交付到 `Wuuuucccyyy/Boundary-aware-Adaptive-RAG-Agent`。该账号为仓库所有者，无需邀请自己。

默认回答器为确定性证据摘录器，不能被称为经过验证的 LLM。提供可选 Chat Completions 接口，真实 API 用量与离线文本 token 代理值分栏。规则路由/检查没有模型 token，但计入处理文本量、模块调用和耗时。

风险：合成数据与手工意图规则共享领域词汇，证据标签验证比真实文档蕴含简单；自动指标只是代理，不等于人类质量；没有真实 API 的结果不支持模型成本节约结论。阶段二是否训练取决于后续自然查询及真实模型实验。
