# 第一阶段正式在线实验报告

**结论：动态边界显著减少了相对全库检索的库调用，但本实验没有证明其比正向或固定边界方案节省实际模型 tokens，也没有证明整体回答质量更高。** 动态方案的规则路由处理量更大。当前更值得先解决自然问法识别和评价偏差，再决定是否开展学习式边界。

## 实验范围与真实性

运行于 2026-10-17，使用用户授权的 DeepSeek API。请求模型 `deepseek-v4-pro`；响应模型：`deepseek-v4-pro`。40题、4方法、2重复，共320次在线问答，全部返回成功且带有真实 usage；无自动重试。离线开发验证不作为本报告的正式证据。

正式实验共使用 **65,225 tokens**（输入 50,278、输出 14,947），320 次模型调用。单独的在线演示及开发连接检查不计入这320次；该总数不是账户全部用量。未引入实时价格，故不报告货币费用。

模型温度0、thinking关闭；统一BM25 top-2、证据检查、生成提示和预算。正向/固定首轮top-1，同样允许追加检索。规则路由/检查不调用模型，API tokens为0，模块工作量与耗时另行完整记录。每种方法串行、问题与方法顺序平衡；服务端缓存usage保留。

数据快照 SHA-256：`8147c1618691f4705e46d8c73b661b7d320946729a6b83d23cc8a25da2e5763b`。代码与测试集哈希、环境和时间见 [manifest](../results/online/manifest.json)，完整协议见 [PROTOCOL](../experiments/PROTOCOL.md)。

## 整体结果

自动质量是冻结的“引用+事实锚点+未知声明”代理分，**不是可靠的真实准确率**，下文披露了评分缺陷。必要源召回仅在可支持子任务上计算。每种方法 n=80。

| 方法 | 自动质量代理 | 首轮必要源召回 | 最终必要源召回 | 检索调用/题 | 模块调用/题 | 实际API tokens/题 | p50 / p95 秒 |
|---|---:|---:|---:|---:|---:|---:|---:|
| all | 0.775 | 100.0% | 100.0% | 5.100 | 10.500 | 204.84 | 1.513 / 2.102 |
| positive | 0.787 | 72.9% | 100.0% | 2.025 | 8.075 | 203.86 | 1.479 / 1.949 |
| fixed | 0.781 | 76.0% | 100.0% | 2.000 | 8.000 | 203.05 | 1.430 / 1.936 |
| dynamic | 0.775 | 95.3% | 100.0% | 1.975 | 7.375 | 203.56 | 1.455 / 1.952 |

动态方案相对全库平均少3.125次检索（约61.3%），但相对正向只少0.05次，相对固定只少0.025次。所有方案通过追加检索达到100%的最终来源和支持文档召回，但仍会因任务解析失败而拒答，说明“找到文档”与“正确用证据回答”是两回事。

全库检索后的无关内容被共同的证据检查器过滤，因此生成模型看到的支持证据常常相同。不能把检索次数下降当作token节约；当前实现几乎没有让动态方法减少实际模型上下文。

| 方法 | 本地文本处理proxy/题 | 无效源调用比例 | 回答覆盖率 | 已回答样本的代理质量 | 可回答性判断正确率 |
|---|---:|---:|---:|---:|---:|
| all | 3785.0 | 62.5% | 57.5% | 0.739 | 82.5% |
| positive | 3356.5 | 31.7% | 57.5% | 0.761 | 82.5% |
| fixed | 3460.4 | 30.4% | 58.8% | 0.766 | 83.8% |
| dynamic | 5757.5 | 29.2% | 57.5% | 0.739 | 82.5% |

本地proxy为每个模块输入输出UTF-8字节数/4的累积，包含重复处理，不是模型tokens或CPU费用估算。动态画像中的任务边界与依据更长，导致该proxy更高。回答覆盖率把含明确拒答的部分回答也算作“未完整回答”。引用有效率在被解析出的引用中为100%，但它忽略了未识别格式，不能证明全部回答忠实。

## 失败与内容复核

以下是开发助手对已保存原文的逐条内容复核，**不是独立人类盲审**，不用于覆盖冻结评分。所有自动失败记录见 [failures.json](../results/online/failures.json)。

| 轨迹 | 观察 | 分类与影响 |
|---|---|---|
| test-10 / dynamic / 0 | “每年能歇几天带薪假”被标为unknown，虽找到了年假文档仍拒答。 | 真实任务分析失败；其他方法也失败。 |
| test-20 / dynamic / 0 | “离开公司、撤掉登录”未映射到离职流程与账号停用。 | 真实口语泛化失败，宽检索无法补救解析缺口。 |
| test-30 / positive / 0 | “填费用的页面进不了”未识别系统访问任务。 | 任务识别失败；且gold把模糊故障当权限问题，本身存在歧义，应允许澄清型答案。 |
| test-04 / dynamic / 0 | 回答正确列出电子发票、行程单和审批编号，但没有30天期限。 | 题目只问凭证；任务级评分要求额外期限，属于过严评分。 |
| test-09 / dynamic / 0 | 正确回答服务台邮箱，但没有工作时间。 | 题目只问邮箱；评分锚点要求18点，属于过严评分。 |
| test-05、06、23、25 / dynamic / 0 | 实际回答内容与库中事实一致，引用写成 `[doc_id: it-…]`。 | 格式协议不符、评分解析漏识别；不能据0分断言内容错误。 |
| test-40 / fixed / 1 | 回答15天并拒答账户余额，未说提前3天申请。 | 题目只问天数；冻结代理得0.5，包含不必要事实要求。 |
| test-39 / dynamic / 0 | 期权模拟税务有证据，明天股价明确无法确定。 | 部分回答与证据缺口处理正确。 |
| test-11 / dynamic / 0 | 同轮选HR与财务，资格和税务都有来源。 | 动态子任务边界保留跨库支持的正例。 |

冻结的拒答识别也是正则表达式，可能把“无法确认真实税法”等谨慎表述当成整体拒答；答案覆盖率与可回答性指标因此也需谨慎。我们保留首轮结果而没有事后修改评分。后续应在独立开发集修正格式和按题事实需求，再冻结新一轮协议。

## 复现与下一步

```bash
python scripts/verify_results.py results/online
python scripts/read_trace.py --id test-04 --method dynamic --repetition 0
python scripts/run_experiments.py --backend deepseek --repeats 2 --output results/new_online
```

先修复评价与自然问法覆盖，加入独立标注、按文档/时间隔离的数据、正向top-k及共享集合选择器下去掉N的消融。动态方案的任务支持矩阵和覆盖策略与负向边界同时变化，不能分离贡献。现在还不足以决定训练对比模型或在线反馈更新。
